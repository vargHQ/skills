# Skill: varg-character-video

From approved character stills to moving, talking video.

Prerequisites: `varg-ai` (auth, render modes, syntax) and `varg-characters`
(cards, scene composites — always approve stills BEFORE paying for video).
For 2+ speakers in conversation, continue with `varg-dialogue-scenes`.

## Decision tree: pick the pipeline first

| The character... | Pipeline | Model |
|---|---|---|
| moves, no speech | image-to-video | `kling_v3` (3-15s int) |
| speaks, you control the exact voice & text | Speech() → image+audio lipsync | `veed_fabric_1_0` |
| speaks a long monologue (up to 60s) or needs full-body gesture | Speech() → image+audio | `omnihuman_v1_5` (expensive, ~1008 cr) |
| speaks in-scene while acting (walks, gestures, ambient sound) | native audio, dialogue in prompt | `kling_v3` + `generate_audio` |
| is already an animated video that needs lips matched to audio | video+audio lipsync | `sync_v2` / `sync_v3` |

Rules of thumb:

- **Voice quality & exact wording matter** (narration, brand scripts) →
  speech-first with `veed_fabric_1_0`. ElevenLabs voices are cleaner and
  reproducible; the text is guaranteed verbatim.
- **Scene realism matters** (character acts while talking, camera moves,
  environment audio) → `kling_v3` native audio. Voice is generated by the
  model — less control, more natural in-scene presence.
- Never guess model IDs or durations — verify in `varg-ai` models.md or
  `GET https://api.varg.ai/v2/pricing`.

## 1. Image-to-video (no speech)

Animate an approved scene still. The prompt describes **motion only** —
never re-describe the image:

```tsx
const vid1 = Video({
  model: varg.videoModel("kling_v3"),
  prompt: { text: "she looks up from the cup and smiles softly, steam \
rising, camera pushes in slowly", images: [scene1] },  // exactly ONE image
  duration: 5,           // integer 3-15 for kling_v3
  aspectRatio: "9:16",
})
```

- `Video()` takes exactly **one** image (first frame). Multiple images error
  (exception: reference-to-video models, see `varg-dialogue-scenes`).
- Good i2v prompts: subject motion + camera motion, 1-2 sentences.
- Add subtle camera work ("slow push-in", "handheld drift") — it adds
  production value for free.

## 2. Talking head — speech-first (recommended)

**One `Speech()` call for ALL lines, then lipsync per segment.** The audio
drives every duration — no hardcoded numbers.

```tsx
// 1. AUDIO FIRST — array children produce timed segments
const { audio, segments } = await Speech({
  model: varg.speechModel("eleven_v3"),
  voice: "EXAVITQu4vr4xnSDxMaL",   // Sarah; any ElevenLabs voice_id
  children: [
    "Hey! I tested this for two weeks straight.",
    "Here is what nobody tells you about it.",
    "Link below — thank me later.",
  ],
})

// 2. Talking clips — image + audio segment → talking video
const talk1 = Video({
  model: varg.videoModel("veed_fabric_1_0"),
  keepAudio: false,                 // voiceover track owns the audio
  prompt: { images: [scene1], audio: segments[0] },
  providerOptions: { varg: { resolution: "720p" } },  // 480p or 720p
})
const talk3 = Video({
  model: varg.videoModel("veed_fabric_1_0"),
  keepAudio: false,
  prompt: { images: [scene3], audio: segments[2] },
})

// 3. B-roll for the middle segment
const broll = Video({
  model: varg.videoModel("kling_v3"),
  keepAudio: false,
  prompt: { text: "close-up of hands opening the product box on a desk", images: [productShot] },
  duration: Math.ceil(segments[1].duration),
})

// 4. Compose — full audio at Render level, crossfades allowed
export default (
  <Render width={1080} height={1920}>
    <Clip duration={segments[0].duration}>{talk1}</Clip>
    <Clip duration={segments[1].duration} transition={{ name: "fade", duration: 0.3 }}>{broll}</Clip>
    <Clip duration={segments[2].duration} transition={{ name: "fade", duration: 0.3 }}>{talk3}</Clip>
    {audio}
    <Captions src={audio} style="tiktok" position="center" />
    <Music model={varg.musicModel("music_v1")} prompt="soft upbeat pop, minimal"
           duration={Math.floor(audio.duration)} volume={0.2} ducking />
  </Render>
)
```

Key mechanics:

- `await Speech({ children: [...] })` returns `{ audio, segments }` with
  word-level timing; `segments[i].duration` drives clip durations.
- **`keepAudio` discipline** — this is the #1 source of double-voice bugs:
  - voiceover mounted at Render level → `keepAudio: false` on EVERY
    generated Video it plays over;
  - no shared voiceover (per-clip audio) → `keepAudio: true` on lipsync
    clips, and use **hard cuts only** (transitions overlap audio).
- `Music duration` must be an **integer** (fractional totals 422) and must
  be set explicitly, otherwise ~60s of music extends the video.
- Portrait input for veed/omnihuman: the character should face camera,
  mouth visible, medium or close framing — use a scene composite where the
  character looks at camera (see `varg-characters`).

## 3. In-scene speech — kling native audio

Dialogue embedded in the video prompt; the model voices it and adds ambient
sound. Best when the character acts while talking.

```tsx
const vid2 = Video({
  model: varg.videoModel("kling_v3"),
  prompt: {
    text: `Same cafe. She lifts the cup, looks into camera. \
She says warmly: "This is my third one today. No regrets." \
Soft cafe ambience, quiet chatter.`,
    images: [scene2],
  },
  keepAudio: true,                 // the clip's own audio IS the soundtrack
  duration: 5,
  providerOptions: { varg: { generate_audio: true } },
})
```

- Quote lines **verbatim** with a delivery direction ("says warmly",
  "matter-of-factly", "whispers").
- Budget ~2.5 words per second of clip; keep lines under ~10 words per 5s.
- For silence: "no dialogue, ambient sounds only".
- Native-audio clips → hard cuts, `keepAudio: true`, no Render-level
  voiceover on top.

### Captions for native-audio clips

`<Captions src>` accepts only a Speech element or an SRT path — it cannot
transcribe a Video's audio. Two-pass workflow:

1. Render once without captions.
2. Transcribe: upload audio via `POST /v2/files`, then `POST
   /v2/transcription` with `{"model":"groq_whisper_large_v3_turbo",
   "audio_url":..., "word_timestamps":true}` (~4 credits).
3. Build a word-level SRT, fix mishears, embed inline (cloud render):

```tsx
const SRT_PATH = `/tmp/proj-${Date.now()}.srt`
await Bun.write(SRT_PATH, SRT_CONTENT)
// <Captions srt={SRT_PATH} style="tiktok" position="center" wordsPerLine={3} />
```

Re-submitting is nearly free (everything cached). If you change any trim,
regenerate the SRT — timings shift.

## 4. Lipsync over existing video

When you already have an animated clip (kling i2v) and a separate voice
track:

```tsx
const animated = Video({
  model: varg.videoModel("kling_v3"),
  prompt: { text: "she gestures while explaining, natural head movement", images: [scene1] },
  keepAudio: false,
  duration: 5,
})
const lipsynced = Video({
  model: varg.videoModel("sync_v2"),
  prompt: { video: animated, audio: voice },
  keepAudio: true,
})
```

Costs two generations (animate + sync) — prefer `veed_fabric_1_0` unless
you specifically need the kling motion.

## 5. Trim dead air, then QA

Generated clips have ~0.2-0.5s warm-up and often trailing silence:

```bash
ffmpeg -i clip.mp4 -af "silencedetect=noise=-35dB:d=0.35" -f null - 2>&1 | grep silence_
```

```tsx
<Clip cutFrom={0.2} cutTo={5.6} duration={5.4}>{vid1}</Clip>
```

- silence at start → raise `cutFrom`; at end → lower `cutTo`.
- Wrong/garbled spoken line → regenerate that Video only.
- Always frame-check the final render (Read frames as images):

```bash
ffmpeg -v error -ss 3 -i out.mp4 -frames:v 1 -vf scale=270:-1 check-s1.png -y
```

Check: lips actually move during speech, identity/outfit match the card,
captions don't cover the face, duration equals the sum of clip durations
(`ffprobe -show_entries format=duration`).

## Render execution

- Always render in **background** (`nohup bun run render ... &` locally, or
  submit `POST /v2/render` and poll `GET /v2/jobs/:id` in the cloud) — see
  `varg-ai` cloud-render/local-render references.
- Keep all prompts byte-identical with the approval pass — the stills are
  then free cache hits and you only pay for the video layer.
